# M1 — swimming and underwater test tank

**Status: source implemented; Unreal build and playtest not yet run.**
The 25 engine-free tests pass, including eleven swimming tests. M0's first
on-machine compile is still unconfirmed; do not treat either milestone as
accepted until the checks below pass on Unreal 5.7.

## Build and prepare

1. Finish [SETUP.md](../SETUP.md) and select branch `ccr-c50880a2-g0siyj`.
2. Close the Unreal Editor. Run `Tools/Build.bat` and wait for
   `BUILD SUCCEEDED`. A full build is required for the new C++ classes.
3. Run `Tools/PrepareM1.bat`. Wait for `M1 PREPARATION SUCCEEDED`.
   This runs Unreal's Python editor scripting and creates:
   - `Content/Maps/M1_TestTank.umap`
   - `Content/Data/DT_SwimTuning.uasset`, imported from `Data/SwimTuning.csv`
4. Open `Paleotrench.uproject`. The startup map should be **M1_TestTank**.
   Press **Play** (not Simulate), then click the viewport to capture input.
5. In **Window → Output Log**, filter `LogPaleotrench`. Expect the M0
   `self-check PASSED` line and
   `M1 diver ready: cruise 240 cm/s, sprint 420 cm/s, tuning CSV`.
   A `fallback` tuning message means preparation/import needs fixing.

Preparation is repeatable: it reimports the CSV and reuses existing tank and
PlayerStart actors. It keeps other actors you add to the map. Run it with the
editor closed, since it opens/saves the map in a separate editor process.
The generated assets are not included in the source change; after verifying
them, commit the two files with Git LFS if you want to share that exact map.

If anything fails, run `Tools/CollectLogs.bat`. It now includes the preparation
log as well as build and game errors.

## Controls

| Action | Keyboard/mouse | Gamepad |
|---|---|---|
| Forward/back, strafe | W/S, A/D | Left stick |
| Ascend/descend relative to your current view | Space / Left Ctrl | Right / left shoulder |
| Look around | Mouse | Right stick |
| Roll | Q / E | D-pad left / right |
| Sprint (hold) | Left Shift | Left stick click (hold) |
| Level the view, keeping heading | R | Right stick click |
| Toggle the temporary headlamp | F | Top face button (Y / Triangle) |
| Release the editor mouse | Shift + F1 | Keyboard needed for editor UI only |
| Stop Play in Editor | Escape / toolbar Stop | Toolbar Stop |

Swim axes follow the camera, including its roll. There is no floor lock or
automatic horizon snapping. `R` is the comfort escape when disoriented.
The headlamp has unlimited power in M1; charge levels and battery costs are M2.
There is no oxygen countdown or fauna yet.

## Acceptance checks

| Check | Expected result |
|---|---|
| Hover with no input for 30 seconds | No falling or buoyant drift with the default CSV. |
| Swim in each direction | Smooth acceleration; forward follows where you look; up/down follow view-up. |
| Hold W and S together, then release one | Opposite input cancels; the remaining key immediately works. Existing momentum still decays. |
| Hold W + D + Space | Same top speed as forward alone, rather than a diagonal boost. |
| Release forward, then reverse | You coast to a stop; reversing takes time rather than instantly flipping velocity. |
| Sprint, turn, then release sprint | Faster swimming and slower turning while moving; speed settles gradually to cruise. |
| Pitch through vertical and make a full roll | No gimbal lock, forced upright snap or sudden camera flip. Level-view restores the horizon. |
| Sprint into all six walls, pillars and slope | No tunnelling, sustained jitter or launch impulses. Sliding along surfaces remains possible. |
| Swim through both gates at different heights | Clear openings are passable; gate edges block movement. |
| Look at the far end with lamp on/off | Blue-green distance fog, subtle mask-like vignette and useful near-field light; darkness does not brighten over time. |
| Gamepad only | All diving actions work; small stick motion allows slow movement; released sticks do not drift. |
| Alt-tab while moving/rolling, release keys, then return | No stuck movement, sprint or roll. If it fails, report the input device and key. |
| Stop/play three times | Exactly one diver; no duplicated movement bindings or extra tank actors. |
| Rerun preparation, reopen and play | Existing hand-placed map additions remain; tuning is reimported; no duplicate tank. |

Depth numbers on the east wall are metres below the ceiling. The tank interior
is 40 × 30 × 16 metres. Default cruise is 2.4 m/s and sprint is 4.2 m/s after
acceleration settles. Collision uses a spherical capsule (68 cm across) for
this greybox; a final prone-diver body is later art/interaction work.

## Frame rate and laptop check

In the console (`~`), try `t.MaxFPS 30`, `t.MaxFPS 60`, and `t.MaxFPS 144`.
Repeat the same straight swim and camera turn. Movement distance and gamepad
turn rate should stay consistent; mouse sensitivity should not change with
frame rate. Return to `t.MaxFPS 0` afterwards.

On the RTX 4060 laptop, use 1080p and Medium scalability. Run `stat unit` and
`stat gpu`; record frame, game and GPU milliseconds while swimming for two
minutes. The initial target is 60 fps (16.7 ms frame budget), **not yet a measured
result**. M1 defaults to direct dynamic lighting with Lumen, virtual shadow
maps and volumetric fog disabled. There is no baked lighting dependency.

## Adjust feel

Edit the **Default** row in `Data/SwimTuning.csv`, then close Unreal and rerun
`PrepareM1.bat`. No C++ rebuild is needed for CSV-only changes.

| Column | Meaning |
|---|---|
| CruiseSpeed / SprintSpeed | Terminal propulsion speed in cm/s. |
| DragPerSecond | Higher values accelerate and stop more quickly. Default 2 gives a 0.5 s response time. |
| BuoyancyAcceleration | World-up acceleration in cm/s²; 0 is neutral, positive rises, negative sinks. |
| MouseSensitivity | Degrees per mouse input unit. Unreal already scales raw mouse counts by 0.07, so 2.5 matches the stock templates. |
| GamepadTurnRate / RollRate | Degrees per second at full input. Set RollRate to 0 to disable roll. |
| SprintTurnScale | Turning multiplier while sprinting and moving. |
| FieldOfView | Camera FOV, 60–120 degrees. |
| bInvertLookY | True reverses vertical look for mouse and gamepad. |
| FinKickInterval | Seconds between fin-kick events; sprinting emits more often. M4 will connect these to AI hearing. |

The importer rejects invalid values before changing assets. Runtime code also
validates the row and warns before falling back to safe defaults.
